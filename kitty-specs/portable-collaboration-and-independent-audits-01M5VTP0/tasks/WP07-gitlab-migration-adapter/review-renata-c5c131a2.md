## Actual supported limits

GitLab REST v4 with explicit supplied PRIVATE-TOKEN; normalized HTTPS /api/v4 root (loopback HTTP only for fixtures). Ordinary public issues/notes are writable. Opened ordinary creates use one mutation; closing an existing issue is supported, while closed creates need explicit opened-state mapping. State/type/label/assignee and existing-target mappings are explicit; assignees are numeric IDs, titles conservatively limited to 255 bytes. Foreign authors/times stay provenance, not impersonation. Confidential/nonordinary/oversized content, MR discussions/reviews, boards/lists and CI remain retrieved inert evidence with honest findings. No native-equivalence or hosted authority claim is made. CI retrieval pins .gitlab-ci.yml; includes/custom/external configs remain reported limits. Uploads require explicit same-origin retrieved-parent selections. API permission/version/tier failures are findings, not complete empty collections. Negative/ambiguous/private recovery needs manual intervention and never retries a create.

The slash-leading-line refusal is deliberately conservative, including whitespace, fences, unknown commands and Unicode line separators. It preserves source text exactly and reports unsupported before Plan writes; the transport repeats the guard for issue/note create/update and the legacy seam. GitLab documents automatic execution when descriptions/comments are saved: [quick actions](https://docs.gitlab.com/user/project/quick_actions/). The DTO/private-note and ID/IID/state-event choices match the [Notes API](https://docs.gitlab.com/api/notes/) and [Issues API](https://docs.gitlab.com/api/issues/); pinned file reads follow the [repository files API](https://docs.gitlab.com/api/repository_files/). These limits are acceptable declared capabilities, not blockers or claims of lossless recreation.
