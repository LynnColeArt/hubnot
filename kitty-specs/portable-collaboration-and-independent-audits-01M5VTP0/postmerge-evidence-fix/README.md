# Post-consolidation Go evidence representation repair

The independent mission review of `170b3254e7ca7422b90fd149c38b9cb6f7fe339d` found a real NFR-003 failure: three historical review overlay inputs became standalone Go test packages under `kitty-specs/` in PRIMARY. Unqualified `go test ./...` and `go vet ./...` tried to compile their references to private root-package fixtures and types. The original failure report and raw failures remain preserved; root recorded NFR-003 as failing before this repair.

The three files were historical overlay inputs, not active product tests. The WP02 `overlay.json` maps a virtual `zz_independent_adversarial_test.go` into the root lane package. The two WP03 `source.json` overlay maps likewise bind a virtual root `zz_wp03_review_test.go` to an external probe. Those maps and the original review reports explain the intended use. Keeping the probe text under a new `hubnot/kitty-specs/...` Go package never made those private root fixtures available.

Exactly three files are renamed from `.go` to `.go.txt`. `evidence-representation.json` records each original/preserved path, SHA-256, byte count, original Git blob, Git mode and filesystem mode. Contents and modes are unchanged. Historical checksum files, reports, overlay JSON, source metadata, raw logs and archives keep their original bytes. To verify an old logical filename, resolve it through this manifest and check its unchanged digest against the preserved text. A deliberate overlay replay can use a temporary resolved overlay map; frozen originals are not rewritten. No build-ignore rule, lint exclusion, product Go source, default, CI command, test assertion or lifecycle status is changed.

The original WP12 v1 guard and its wrappers/receipts/checksum files remain byte-identical at their original paths. That guard excluded mission metadata from its Go comparison, which allowed false confidence after consolidation. Its historical c4 lane results do not prove that a later PRIMARY contained the same repository-wide Go inputs. The new `source-guard-v2.sh.txt` supersedes future verification: it compares **all tracked Go and module/workspace inputs**, including governance directories, in a separate step without metadata exclusions. It also detects untracked Go/module inputs in Go-discoverable paths even when Git ignores them. Only Go's inherent hidden/underscore/testdata/vendor discovery skips apply to untracked paths; tracked Go is checked even there. Harmless non-Go governance records may still differ.

`guard-v2-controls.sh.txt` exercises an isolated Git fixture: unchanged input and non-Go metadata pass; tracked normal and hidden metadata Go fail; an untracked Gitignored file that really appears in `go list ./...` fails; a Go-inherently ignored hidden directory does not create a false package. The v2 guard also rejects the actual three overlays before their rename, then accepts the representation-only working tree. No product test was edited to make these controls pass.

`approved-c4-package-graph.txt` comes from actual `go list ./...` over an isolated `git archive` of approved `c4aaa4e840420b07d83617c6373d6f4088e2c077`. `check-go-discovery-v2.sh.txt` requires actual PRIMARY to have that exact twelve-package graph, zero tracked evidence Go files, and matching all-Go/module inputs. `run-primary-full-gate.sh.txt` pins the actual PRIMARY HEAD and runs the required fresh, unfiltered `go test -race -count=1 -timeout 20m ./...` with before/after source checks. New full results must come from PRIMARY at the committed fix, not the retired lane or a cached package result.

Actual source-bound preflight/full results will be archived separately after execution. This repair itself does not restore NFR-003 to passing or imply independent approval. Root owns the canonical verdict and independent follow-up review. Existing c4 release artifacts remain valid for c4; any newer package proof must name its actual committed source.
