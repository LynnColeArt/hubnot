# Acceptance quickstart

Proposed command families become executable public acceptance scenarios; keep
final flags in sync with operator docs.

1. Build ordinary, `nogithub` and `noforge` binaries with Go/Git only.
2. Create native signed resources in temporary Git repositories; plan and inspect
   a local-to-archive migration before explicit apply.
3. Import to a separate local repository with an explicit governance choice.
   Verify exact native bytes/signatures/dependencies and inspect foreign records
   and downloaded attachment bytes with adapters and credentials absent.
4. Exercise guided and saved-plan GitLab-fixture→GitHub-fixture migration. Check
   EOF refusal, capability losses, stale baselines and uncertain-write recovery.
5. Opt a temporary project into owner/requester/executor roles. Authorize a rule
   as its sole owner, audit already-merged code without a proposal, and explicitly
   create linked follow-up work. Reprocessing must not flood duplicate issues.
6. Check that audit failure neither blocks nor qualifies merge evidence; sync to
   an ordinary temporary Git remote and inspect from a keyless clone.
7. Build release archives twice from the committed integration revision and check
   deterministic contents. Separate target runtime evidence from compilation.

Do not mutate real provider accounts, public releases/tags, or source projects
as an acceptance shortcut. Queueing, scheduling and batching remain later work.
