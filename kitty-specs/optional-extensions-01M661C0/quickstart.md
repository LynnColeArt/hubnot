# Planned consumer and qualification walkthrough

These are acceptance steps for later implementation, not commands that exist today.

1. Capture the integrated beta/default baseline and existing exact signed goldens.
   Run native journeys without any extension configuration. Preserve original failures.
2. Build the standard and combined native-only candidate with Go-only tooling; build
   reference processes as separate optional test assets.
3. Inspect/register the fake-tracker manifest while disabled. Show declaration,
   grants, compatibility, enabled state and availability separately. Prove no launch.
4. Enable read-only locally. Send an ungranted handwritten mutation and wrong-repository
   request; require the exact structured refusal and no forbidden effects.
5. Grant only issue create/comment/revise/observe. Import fake issue/comment, lose
   acknowledgement, restart and recover the exact original native actor/key result.
6. Make a native edit and export it using the connector's private external journal.
   Repeat observation/restart: no duplicate native facts or echo loop. Introduce
   concurrent edits and require explicit conflict/stale diagnostics.
7. Define document/list/ticket type declarations through the generic artifact path.
   Store representative directive/tactic documents, relationships, a pack and an
   exact-revision charter selection. Search without activating any of it.
8. Publish an unrelated inventory/custom ticket/list model through the same generic
   contract. Core code must not require doctrine names or domain-specific handlers.
9. Revise schemas, preserve original records, create conflicting heads and explicitly
   resolve them. Test missing dependencies, unsupported schemas and every size bound.
10. Exchange selected public closure through a real bare remote into a second
    independently initialized clone. Do not copy credentials/grants/keys/private
    journals. Disable/remove the consumer and inspect/search/export generically.
11. Exercise contribution-enabled native visibility/moderation and invalidated
    checkpoints. Custom writes in that policy configuration must advertise and
    enforce their initial unsupported status before effects.
12. Cancel/crash/disable a child; confirm finite cleanup and unrelated native/module
    availability. Verify no signer initialization by reads and no private-state leaks.
13. Repeat the default acceptance matrix and paired performance measurements. Run
    fixed-head Go checks and exact package journeys on every claimed target/variant.
14. Obtain independent native-user and consumer-author feedback and a focused boundary
    review. Record unresolved findings as blockers; no automatic release/publication.

Consult contracts/host-v1.md, contracts/artifact-v1.md and
contracts/default-workflow.md for the normative planned boundaries. Actual CLI
spellings and complete executable contract fixtures are pinned in the work packages
before implementation, rather than pretending these planning steps already execute.
