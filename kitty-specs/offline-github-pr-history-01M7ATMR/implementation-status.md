# Implementation and verification

Workbox reads active CI configuration from committed Git objects and sends edits through Settings. Native issue reads remain authoritative. Index reconciliation uses Hubnot’s selected event history and pinned Git refs inside a SQLite savepoint. Removed replicated refs lose their projected rows and restored issues retain their presentation numbers. Memory rows are signature-verified and ref-reconciled. Native memory lifecycle and coverage reporting remain a separate gap. Older Hubnot binaries keep the signature-based fallback where the visible-log command is absent.

The installed Hubnot registry supplies migration source/destination pairs and required, optional and enumerated non-secret configuration fields. The browser and MCP share planning, inspection, apply, resume and pagination. Review confirmations bind to the saved plan. Workbox can still inspect saved sessions when a provider is absent. Provider-specific record kinds, capability effects and credential instructions still come from native plan findings or the CLI. The custom-provider tests cover offline discovery, path restriction, and native plan and apply using an enumerated field. A separate build with the GitHub adapter excluded verifies that its paths disappear. The browser was exercised with standard and GitHub-disabled binaries. A separately built custom provider was exercised through the native CLI test fixture.

The offline fixture imported 24 Hubnot PRs explicitly into a disposable repository. Browser and MCP showed 23 merged and one closed across pages of 10, 10 and 4 with external browser requests blocked. Native proposals remain separate. A fixture upstream edit stayed invisible until explicit reimport, which updated the local revision without duplicating its source identity.

Pagination defaults to 10 through the settings-file `pageSize` (1 through 50). It covers the primary issue, discussion and reply, proposal, PR, CI, Memory, Explore, migration-session and activity views. Existing cursor continuations and legacy issue MCP shape are preserved. Issues, discussions and pull requests reuse accessible text status tags. A full label, narrow-screen and keyboard review across all collections remains open.

Chrome reopened and resumed a saved local migration after a forced Workbox server termination. MCP reported the same confirmed action count. The native lost-acknowledgement test verifies reconciliation after the destination write succeeded. The Workbox production build and focused Linux browser/MCP tests passed. Full OS qualification remains deferred.
