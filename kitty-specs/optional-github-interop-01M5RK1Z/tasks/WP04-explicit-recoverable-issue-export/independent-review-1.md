## Acceptance assessment
The neutral exporter selects a verified native issue snapshot, exact head/actor/full state and bounded signed comments, refuses conflicts, and revalidates historical checkpoint content against signed events. Native-only criteria/relations/metadata have a visible appendix for other destinations; source-body exports require exact signed source provenance and refuse unrepresentable extras. Imported author/time remain descriptive claims. Comment attribution and proof include actual native actor/time/IDs and complete body digest. Same-source imported comments are skipped only with validated deterministic import provenance; externally deleted originals are not recreated. Reverse import suppression requires a complete exact marker plus an actual signed native comment rendered identically. Marker prose/forgeries remain ordinary imported content rather than erasing data.

Prepared/in-flight/confirmed intents bind exact payload, native snapshot and destination. The executor saves in-flight before one mutation and sanitizes callback failures. Recovery accepts only verified positive matching observations; a complete negative scan never authorizes another uncertain create. Lost issue/comment responses, ignored API fields, duplicate mappings and forged payloads fail or reconcile conservatively. Closed issue creation is a verified open create followed by a separate guarded closed update. Export baselines cover normalized transmitted projection, separately from import-managed digests. Unchanged-local remote edits are retained without turning them into a new overwrite baseline; competing edits refuse. Fresh-clone marker recovery requires actual signed historical rendering and exact intended fields.

Dry-run performs reads/preflight only. Credentials are required before writes and are not journaled. Checkpoints reuse strict bounded private atomic Git-directory storage and the single-local-publisher lock. Generic coordinator code imports internal/forge, not GitHub DTOs or HTTP; the binding provider-neutral amendment supersedes the earlier request to tag the generic exporter !nogithub. Only the concrete GitHub adapter/client is excluded. Distinct resource capability dispatch remains WP03; later native resource adapters are not claimed as shipped by this issue-only WP. No live GitHub mutations were performed.
