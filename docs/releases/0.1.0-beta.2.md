## Actual bounded checks

The supplied native harness is **non-race** on every target. Each invocation
used the original caps: bundle 1 minute, invalid package selection 1 minute,
install/runtime 2 minutes, and each extension variant 3 minutes. All stages
exited 0 on all three supported targets; no failing test was repaired or rerun
on Golden Goddess or Pink Menace.

| Check | What passed |
| --- | --- |
| Complete bundle | Nine archive bindings, provenance, BUILD metadata, exact source/compiler/version, checksums and native selection |
| Invalid selection | Missing/malformed/mismatched packages refuse without a source-build fallback |
| Install/runtime | Byte-preserving installation, version, memory record/regex and invalid-regex refusal, native migration; literal `/tmp` and `/var/tmp` on Mac with child TMPDIR absent |
| Extension smoke, each variant | Registration, enablement, explicit run, no implicit launch and raw artifact type read; mandatory exact-source references, missing-reference negative control and no fallback |
| Preservation | Final candidate/test-kit checksums pass; exact-source checkout stays clean |

Each extension receipt selects five original roots and excludes 201 of the
206-root canonical inventory, with `group=smoke`, `result=PASS` and
`source_fallback=false`. Inventory SHA256:
`6286bcb20f796972494a94cf151a9ddedde4461280084b1d02318a36bb813f2c`.

Golden Goddess's rounded five-stage durations were 1s/1s/1s/3s/2s. Pink Menace
reported 17 seconds total across rounded stages. The Linux AMD64 download-back

## Known replication performance issue

Beta.2 retains the receipt-growth problem reported in
[issue #26](https://github.com/LynnColeArt/hubnot/issues/26): each replication
receipt records the whole reachable object closure, and replication-aware
reads repeatedly load the growing receipt history. Long-lived clones can
become progressively slower. The reported production timings belong to Andrew's
deployment, not a benchmark from the bounded package smoke above.

[PR #32](https://github.com/LynnColeArt/hubnot/pull/32) merged on `main` on
November 3, 2026, adding delta receipts, settled-acceptance preservation and
transaction-ID collision protection. It was open before packaging but is
**not included in the published beta.2 bytes**. The merge does not change this
release; distribution of the fix requires a newly packaged/qualified version.
Do not delete private acceptance
receipts to work around the slowdown; they participate in recovery and trust
checks. See [release review procedure](../releasing.md#release-review-checklist).

## Mac signing and download experience

**Developer ID signing and Apple notarization are pending follow-up work.**
Pink Menace tested terminal-acquired, linker ad-hoc-signed binaries without
quarantine. Browser-download/Gatekeeper execution of these exact bytes was
**NOT_RUN**. The earlier quarantined-browser failure in
[issue #24](https://github.com/LynnColeArt/hubnot/issues/24#issuecomment-6595409846)
remains unresolved; terminal runtime success does not certify that path. No
quarantine was stripped or host security setting disabled to obtain the pass.
Re-signing or notarization that changes package bytes requires fresh digests
and the relevant runtime/distribution checks.
